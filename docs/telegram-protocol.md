# Протокол multitest ↔ Telegram-бот (v1)

Скрипт говорит только с API бота (`MT_BOT_API`, по умолчанию `https://mtbot.sixseven.cam`) и
никогда — с api.telegram.org: токена бота в скрипте нет и быть не может. Здесь описано всё, что
сервер отправляет боту, — чтобы это можно было проверить.

## Ключ сервера

- Генерирует сам сервер при привязке: `mtk_` + 64 hex из `/dev/urandom`.
- Уходит только заголовком `Authorization: Bearer mtk_…`, через конфиг curl из stdin (`-K -`):
  в argv и `ps` его нет. Бот хранит лишь SHA-256 ключа; ни в одном ответе ключа нет.
- Лежит в `/etc/multitest/agent.conf` (0600, каталог 0700) вместе с ID сервера, адресом API и
  юзернеймом бота. Файл читается построчно по белому списку ключей, никогда не через `source`.
- Права ключа: только свой сервер — статус, отвязка, загрузка сводки.

## Транспорт

- Только `https`: `curl --proto =https --proto-redir =https`, без `-L` и `-k`,
  `--connect-timeout 10`, `--max-time` по запросу (ниже).
- Запросы — поля форм (`--data-urlencode`) или multipart (`-F`). Ответ — `text/plain`, первая
  строка: глагол и токены через пробел; в конце допустимы `ключ=значение` (будущие поля).
  Незнакомый глагол — не ошибка протокола: лог и повтор позже.
- Общие ответы: `retry <секунды>` — повторить позже; `revoked` — сервер отвязан в боте (только
  по этому ответу скрипт стирает ключ); `err <код>` — ошибка запроса. Голый HTTP 401 ключ **не**
  стирает: это может быть сбой прокси или базы.
- Всё, что прислал бэкенд, проходит через `mt_clean` (без ESC и управляющих) перед выводом.

## Привязка (device flow)

| Шаг | Запрос | Ответ | Таймаут |
|---|---|---|---|
| 1 | `POST /v1/pair/start` — `ip4 ip6` (маской), `country city asn cpu cores ram disk os virt v` | `ok <code> <ttl> <match>`, далее строки QR | 30 c |
| 2 | `POST /v1/pair/poll` | `pending` · `approved <кто, %-кодировка>` · `denied` · `expired` | 15 c |
| 3 | `POST /v1/pair/confirm` — `answer=yes\|no` | `ok <server_id>` · `cancelled` | 30 c |

1. Скрипт печатает `https://t.me/<бот>?start=p_<code>`, QR и «Код для бота: `<match>`».
2. В боте открывается карточка с данными сервера и тремя кодами; неверный код отменяет привязку.
3. Скрипт опрашивает `poll` раз в 2 с. На `approved` показывает, **какой аккаунт** подтвердил, и
   спрашивает с клавиатуры «это вы?». Только после «да» уходит `confirm`, и пишется конфиг.

## Быстрая привязка (код из бота)

В боте «Добавить сервер» выдаёт команду с одноразовым кодом `mtp_` + 24 символа (действует 15 минут,
новая команда гасит прежнюю; бэкенд хранит только хеш кода):

```
curl -fsSL <скрипт> -o /usr/local/bin/multitest && chmod +x /usr/local/bin/multitest && multitest --pair mtp_…
```

| Шаг | Запрос | Ответ | Таймаут |
|---|---|---|---|
| 1 | `POST /v1/pair/claim` — заголовок `X-Pair-Token: mtp_…`, поля как у `pair/start` | `approved <кто, %-кодировка>` · `err token` (404) · `err limit` (409) | 30 c |
| 2 | `POST /v1/pair/confirm` — `answer=yes\|no` | `ok <server_id>` · `cancelled` | 30 c |

- Код — заголовком через `-K -` (stdin curl), как и ключ: в argv curl и в адресе его нет.
- Аккаунт известен по коду, поэтому ни ссылки, ни QR. Но «Привязать сервер к Telegram-аккаунту
  `<кто>`?» на сервере остаётся: иначе чужая команда привязала бы ваш сервер к чужому аккаунту.
- Сообщение с командой в боте меняется на «осталось подтвердить на сервере», потом — «сервер привязан».

Вопросы читаются только из терминала (`/dev/tty`), не из stdin: при `curl … | bash` stdin — это
сам скрипт. Без терминала привязка отказывается работать.

## Сервер

| Запрос | Ответ | Таймаут |
|---|---|---|
| `POST /v1/agent/hello` — `v`, `p=1`, `t=<id тестов через запятую>`, `agent=0\|1`, `lim=<gap,day,heavy>` | `ok` · `revoked` | 15 c |
| `GET /v1/agent/poll?wait=25` (≤ 50) | `idle` · `job <job_id> <id тестов через запятую>` · `revoked` | wait + 35 c |
| `POST /v1/agent/jobs/<job_id>/event` — `type=start\|progress\|beat\|failed`, `i`, `n`, `t`, `reason`, `wait` | `ok` · `cancel` | 15 c |
| `POST /v1/agent/runs` — multipart: `summary`, `key`, `job_id`?, затем `page` × N | `ok <run_id>` · `pending` · `blocked` · `revoked` · `retry <с>` · `err …` | 180 c |
| `POST /v1/agent/bye` | `ok` | 15 c |

- `key` — ключ идемпотентности `run-` + 16 hex: повтор после таймаута не создаст второй пост.
- `page` — PNG страниц альбома по порядку: первая — обложка (≤ 13 страниц, ≤ 3 МБ каждая). Скрипт шлёт
  не больше 10 — столько помещается в один альбом Telegram; лишние страницы склеивает попарно. Если
  страниц больше 10 (старые версии), бот отправит лишние отдельным альбомом выше поста.
- `blocked` — пользователь заблокировал бота: ключ цел, сводки возобновятся после разблокировки.
- `agent=1` шлёт служба `multitest-agent` при старте, `agent=0` — при выключении: бот показывает кнопку
  «Запустить тест», только пока служба есть. `lim` — локальные лимиты сервера, бот их только показывает.

## Задания (запуск из Telegram)

- Строка задания: `^job [A-Za-z0-9_-]{16,32} [a-z0-9_,]{1,200}( [a-z]{1,16}=[A-Za-z0-9_.,:-]{0,64}){0,8}$`.
  Каждый id теста — из каталога скрипта, иначе `failed reason=bad_tests`. Повтор того же `job_id` агент
  игнорирует (помнит последние 20).
- Перед стартом — локальные лимиты: отказ `failed reason=local_limit wait=<с>`; идёт другой прогон —
  `failed reason=busy`.
- `start` (`n`), затем `progress` перед каждым тестом (`i` из `n`, `t` — id), `beat` раз в 15 с. Ответ
  `cancel` — в боте нажали «Остановить»: агент гасит группу процессов текущего теста и отправляет
  сводку из готовых. Тест дольше ETA × 3 (≤ 30 мин) и прогон дольше 60 мин останавливаются сами.
- Сводка уходит в `runs` с `job_id` — это закрывает задание (`done` или `cancelled`). Нет `beat`
  120 с — бот закрывает задание как потерянное; `queued` 10 мин без агента — истекает. Автоповтора нет.

## summary.txt (v1)

Строка на запись, поля через `\x1f` (как в `.metrics`/`.services`), ≤ 200 символов в поле,
переводы строк и управляющие символы вычищены. IP — только маской, hostname — нет.

```
v␟1
sys␟<ключ>␟<значение>            version date country city asn ip4 ip6 cpu cores ram disk os virt kernel cc qdisc uptime_s
test␟<id>␟<ok|err|skip>␟<ключевая цифра>␟<0|1 — есть ли данные>
metric␟<id>␟<подпись>␟<значение>
best␟<id>␟<значение>␟<город>␟<up|down>      лучшая скорость (iPerf3, bench.sh)
svc␟<id>␟<имя>␟<ok|warn|bad|na>␟<значение> чипы доступа к сервисам и сайтам
```

`id` теста — имя функции без `run_` (`ip_region`, `iperf3_ru`).
