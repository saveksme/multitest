# Multitest

Интерактивный bash-скрипт для диагностики и тестирования Linux-серверов. Объединяет популярные инструменты проверки в одном меню.

## Быстрый старт

**Запуск без установки:**

```bash
bash <(curl -sL https://raw.githubusercontent.com/saveksme/multitest/master/multitest.sh)
```

**Установка как команда `multitest`:**

```bash
curl -sL https://raw.githubusercontent.com/saveksme/multitest/master/multitest.sh -o /usr/local/bin/multitest && chmod +x /usr/local/bin/multitest && echo "Установлено! Запуск: multitest"
```

После установки скрипт доступен из любого места:

```bash
multitest
```

### Мультитест и сводка-альбом

При выборе **Мультитеста** открывается список тестов с отметками:

| Клавиша | Действие |
|---------|----------|
| `↑` `↓` (или `k` `j`) | перемещение по списку |
| `ПРОБЕЛ` | отметить / снять тест |
| `A` / `N` | отметить все / снять все |
| `F` | только быстрые (до минуты) |
| `ENTER` | запустить отмеченные |
| `Q` | выйти без запуска |

Буквы принимаются и в русской раскладке — по той же физической клавише (`Ф` вместо `A`, `Т` вместо
`N`, `А` вместо `F`, `Й` вместо `Q`), чтобы не переключать раскладку ради одной клавиши.

Рядом с каждым тестом — примерное время прогона и пометка, если под него придётся доставить пакет;
внизу — сколько всего отмечено, суммарное время и список пакетов к установке. Ставится **только то,
что нужно отмеченным тестам**: выбрали одну проверку блокировок — sysbench и iperf3 на сервер не
поедут. В терминале без ANSI (или при запуске через `wget -qO- … | bash`) остаётся ввод номеров
строкой: через пробел/запятую, диапазоны вида `4-7`, Enter — все.

Во время прогона каждый тест стартует автоматически через 5 секунд; `Ctrl+C` пропускает текущий,
`s` — пропуск, `q` — выход.

**Рекомендация BBR + Cake.** Перед сетевыми тестами (iPerf3, YABS, bench.sh) скрипт один раз за
запуск спрашивает, не включить ли BBR + Cake: без него одиночный TCP-поток на дальнем маршруте
недобирает, и скорость в тестах выходит ниже реальной. `y`/`д` включает — это та же утилита из
меню, с сохранением прежних значений для отката; `Enter` — отказ, и больше вопрос не возникнет
до конца сеанса. Вопрос задаётся один и на весь мультитест (если среди выбранного есть хоть один
сетевой тест), и он же — при запуске такого теста по отдельности из главного меню; если BBR +
Cake уже включены, ничего не спрашивается.

По завершении формируется **сводка-альбом** и заливается на imgdb одним запросом — в консоль
выводится **одна ссылка** вида `https://imgdb.io/a/<id>`. Внутри — **страница на каждый тест**.

**Оформление — Material 3 Expressive, тёмная тема** (концепт 5b): одна тональная палитра M3 из
оранжевого исходного цвета, шрифт [Onest](https://fonts.google.com/specimen/Onest), иконки Material
Symbols. Главную цифру страницы держит фигура M3 Expressive — «печенька» или «солнце», данные идут
сегментированными списками, скорость — волнистыми шкалами. Цвет несёт смысл: салатовая плашка —
сервис видит другую страну или ответил с оговоркой, красная — блок или ошибка, тихий текст — всё как
ожидалось.

- **обложка**: дата, замаскированный адрес крупно, флаг и «город, страна», ASN (и IPv6, если он есть)
  рядом с «печенькой» «выполнено / запущено»; «Сервер» — сетка характеристик (процессор с ядрами,
  память, диск с заполненностью, система, виртуализация, ядро, BBR/qdisc, аптайм по-русски, load);
  «Тесты» — оглавление альбома: иконка, что проверяет тест и его ключевая цифра («NL · 26/30»,
  «до 2140.5 Мбит/с», «риск Low · 1 блок», у пропущенных — статус); невыбранные тесты — контурными
  чипами «Не запускались». Имя хоста на картинку не выводится, оно у большинства VPS выдаёт панель или
  провайдера целиком;
- **страница теста**: крупный заголовок и строка о том, что тест проверяет, затем свой макет под
  данные теста:
  - **IP Region** — «печенька» с консенсусом и «26 / 30 источников называют Нидерланды», кто
    ответил иначе и кто не ответил; сервисы с логотипами (Simple Icons, встроены в скрипт) и
    плашками ответов — флаг и код страны, да/нет; GeoIP-базы сеткой в четыре колонки;
  - **iPerf3** (и tlab) — максимум крупно, в «солнце» минимальный пинг, по городам две волнистые
    шкалы: приём и отдача на общей «круглой» шкале (2500, 5000…);
  - **YABS** — fio 4K и 1M в фигурах, «Сервер», Geekbench 6 (если был), «Сеть» с флагами стран,
    провайдерами и скоростью в Гбит/с;
  - **Censorcheck** (геоблок, DPI, tlab) — сколько сайтов открывается, «печенька» с числом
    блокировок, список сайтов с плашками «доступен / редирект / блок»;
  - **IP Check Place** и **IPQuality** — доступ к стримингам и AI-сервисам (регион с флагом,
    «блок», «без Premium»), уровень риска и тип IP, оценки баз риска, DNSBL, Port 25;
  - **bench.sh** — I/O диска, «Сервер», скорость до узлов с флагами;
  - **sysbench CPU** — events/s крупно, задержка в «солнце», детали сеткой;
  - **Ping-карта** — средний пинг из России, худший узел, узлы по группам (Россия / Соседи /
    Европа / Мир) с задержкой на волнистой шкале и потерями;
  - пропущенный или упавший тест получает свою страницу со статусом, а тест, в выводе которого
    парсер ничего не узнал, — сетку распознанных метрик;
- строка «адреса · гео · дата», номер страницы и **подпись спонсора** повторяются на **каждой**
  странице: из альбома пересылают по одной картинке, и страница без них уезжает в чужой чат как
  результат неизвестно чьего сервера и без единого упоминания, откуда она.

Оригиналы (PNG и SVG рядом) остаются локально в `/tmp/multitest-summary-<ts>/pages/`.

**Подпись спонсора.** Стоит в подвале каждой страницы, под тонкой линией: слева `multitest v2.0`,
справа `powered by` над маркой STENCLOUD, разделитель, промокод и строка «флаги 🇳🇱 🇪🇪 · скидка ·
бот». Марка — вектор (`AD_LOGO_STEN` / `AD_LOGO_CLOUD`), обведённый потрейсом с
[`assets/brand/stencloud.png`](assets/brand/stencloud.png); читаемая копия контуров лежит рядом в
[`stencloud.svg`](assets/brand/stencloud.svg). В подвале марка одноцветная, как в макете: чёрточка и
точки облака вырезаны, сквозь них виден фон. Промокод, скидка и бот задаются в шапке скрипта —
`AD_PROMO`, `AD_DISCOUNT`, `AD_BOT`; ширина подписи считается по ним.

**Шрифт и ассеты.** Сводка набрана Onest (OFL): шесть начертаний 400–900 скрипт ставит в fontconfig
сам — адреса TTF спрашивает у Google Fonts, запасной источник — npm-пакет
`@expo-google-fonts/onest` на jsDelivr; не вышло ни там, ни там — Roboto/Noto/DejaVu из пакетов.
Всё остальное вшито в скрипт, чтобы он оставался одним файлом: иконки Material Symbols Rounded
(Apache-2.0) — путями, логотипы Simple Icons (CC0), круглые флаги
[circle-flags](https://github.com/HatScripts/circle-flags) (MIT) для ~70 частых стран — редкие
догружаются с jsDelivr, а без сети рисуется кружок с кодом страны. Ширина строк считается по
таблице ширин глифов Onest — так плашки, переносы и многоточия совпадают с макетом, а рендер
обходится без единого лишнего процесса в горячих местах.

**Почему альбом, а не одна картинка.** Telegram при отправке «фото» ужимает длинную сторону до
~1280 px (у новых клиентов и с галочкой HD — до 2560) и перекодирует в JPEG: одна длинная сводка
приезжала в чат с масштабом 0.2–0.4×, и мелкие подписи превращались в пару физических пикселей под
JPEG-звоном. Страница альбома — 1280 логических px в ширину, кегли крупные (основной текст 20–26 px),
длинная сторона после рендера не больше 2560 — мессенджеру пересчитывать почти нечего. Надёжнее
всего слать страницы **файлами** (в Desktop — «Send as file» / `Ctrl+Shift`+перетаскивание, на
телефоне — из «Файлов», не из галереи): документы Telegram не трогает вовсе.

Поведение настраивается переменными окружения:

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MT_ALBUM` | `1` | `0` — одна длинная картинка: все страницы стопкой |
| `MT_MAXSIDE` | `2560` | потолок длинной стороны страницы, px |
| `MT_PAGE_SCALE` | `2` | во сколько раз рендерить страницу (ширина = 1280 × scale) |
| `MT_FLAG_FETCH` | `1` | `0` — не догружать редкие флаги из сети (будут кружки с кодом) |

```bash
MT_ALBUM=0 multitest   # все страницы одной длинной картинкой
```

**Двойной стек.** Адреса определяются порознь (`curl -4` / `-6`) — без этого на dual-stack сервере
в отчёт попадал только IPv6, а IPv4 не показывался вовсе. Гео считается по IPv4, если он есть:
у туннельных брокеров IPv6 нередко «прописан» в другой стране, и это отдельный факт, а не гео
сервера. IP Region разбирает обе колонки таблицы: к метрикам добавляются консенсус и совпадения
по IPv6 и счётчик **v4≠v6** — сколько сервисов видят разные страны по стекам, ради этого числа
двойной стек и проверяют. У сервиса, который отвечает по стекам по-разному, показываются оба
ответа (`NL · DE`). Если IPv6 на сервере нет, ничего из этого не появляется.

Рендер SVG → PNG: `rsvg-convert` (или ImageMagick) — ставится автоматически.

**Хостинг.** Альбом заливается на **imgdb.io** ([API](https://imgdb.io/docs) — анонимно, без ключа
и регистрации, работает с VPS): все страницы уходят одним `POST /api/v1/album`, в ответ приходит
одна ссылка. Потолки хостинга — 64 картинки на альбом, 16 МБ на картинку, 150 МБ на запрос,
250 сохранённых картинок в сутки на IP; тестов в скрипте двенадцать, упереться в них нечем.
Двухшаговый вариант API (сначала `/upload` каждой картинки, потом сборка по `id`) не используется:
он на случай запросов тяжелее 150 МБ, а страницы весят десятки килобайт — зато каждый лишний
запрос это ещё один шанс упасть на полпути.

Если альбом собрать или залить не вышло, скрипт молча откатывается на прежний путь: одна длинная
картинка и перебор запасных файлообменников (x0.at, catbox, litterbox, uguu и т.д.). Примечание:
анонимная загрузка файлов на catbox с хостинг/VPS-адресов им блокируется (HTTP 412 «Invalid
uploader»), а uguu.se удаляет файлы через 3 часа — поэтому основной imgdb.io.

**Срок жизни ссылки** (и одиночной картинки, и альбома) задаётся переменной `MT_IMGDB_TTL`
(секунды); по умолчанию `259200` — 72 часа.
Хостинг принимает только значения из своей таблицы, любое другое молча превращается в те же 72 часа:

| `MT_IMGDB_TTL` | 3600 | 7200 | 18000 | 43200 | 86400 | 259200 | 604800 | 1209600 | 2592000 | 7776000 | 0 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| Ссылка живёт | 1 ч | 2 ч | 5 ч | 12 ч | 24 ч | 72 ч | 7 дней | 14 дней | 30 дней | 90 дней | бессрочно |

```bash
MT_IMGDB_TTL=0 multitest   # бессрочная ссылка ценой качества картинки
```

**Почему 72 часа, а не бессрочно.** Всё, что дольше, imgdb пережимает — и заметно. Замер: один и
тот же файл, отличается только `ttl`.

| `MT_IMGDB_TTL` | хранит | уникальных цветов |
|---|---|---|
| до загрузки | 176 КБ | 825 |
| `259200` (72 ч) | 71 КБ | **252** |
| `604800` и дольше, `0` | 59.6 КБ | **17** |

Для оформления 5b это критично: тональная палитра, флаги, плашки и сглаженные края фигур и волн на
17 цветах разваливаются — слоты в палитре достаются цветам по числу пикселей, и всё мелкое (флаги,
салатовые и красные плашки) приезжает в чат выцветшим. На 72 часах палитру не режут вовсе. Ставить
`MT_IMGDB_TTL=0` по-прежнему можно, но картинка тогда заметно посереет.

Реальный срок скрипт показывает не по запрошенному `ttl`, а по полю `expires` из ответа API —
если хостинг откатит значение на дефолтные 72 часа, в выводе будет именно 72 часа.
SVG хостинг не принимает: если хоть одна
страница не отрендерилась в PNG, альбома не будет — скрипт уйдёт на одиночную картинку, а если и
она осталась в `.svg`, запрос к imgdb пропускается и работают запасные файлообменники.

### Telegram-бот (Утилиты → Telegram-бот)

Сервер привязывается к боту [@multitestus_bot](https://t.me/multitestus_bot), и сводка мультитеста
приходит прямо в Telegram **одним альбомом**: обложка и страницы тестов, а пост по общему шаблону
тестов VPS — в подписи (хостинг и страна, цена, железо, скорость до РФ, гео, отзыв, «Реф | Не реф»,
хэштеги). В альбоме Telegram не больше 10 картинок, поэтому при 10–12 тестах соседние страницы
склеиваются попарно: короткие — одна под другой, длинные — рядом. Оригиналы страниц остаются на сервере.

Оформление — форма под постом: сверху видно, что заполнено; нажмите поле (описание, цена, ссылки,
название, страна, заявленный канал; в «Ещё» — тариф, оценка, промокод, хэштеги, строки поста)
и пришлите значение. Ссылки — реф и обычная, каждая по желанию: https://…, просто домен
(xorek.cloud) или Telegram-бот через @.
Просто текст без выбора поля станет описанием. «Готово» → «Поделиться» отправит пост с обложкой
в любой чат или канал; альбом целиком — пересылкой.

**Привязка** — «Утилиты → Telegram-бот» в меню или одной командой:

```bash
bash <(curl -sL https://raw.githubusercontent.com/saveksme/multitest/master/multitest.sh) --pair
```

Скрипт печатает ссылку на бота, QR и код. В боте выберите этот код из трёх, а на сервере ответьте,
что подтвердили именно вы: скрипт покажет, какой Telegram-аккаунт нажал кнопку. Ответы читаются
только с клавиатуры, поэтому привязка работает лишь из терминала. Нужны права root.

| Параметр | Что делает |
|---|---|
| `--pair` | привязать сервер (на уже привязанном — предложит привязать заново) |
| `--tg-status` | привязан ли сервер и есть ли связь с ботом |
| `--unpair` | отвязать сервер и удалить ключ (то же — кнопкой в боте) |

**Что хранится и что уходит.** Токена бота в скрипте нет — скрипт говорит только с API бота
(`https://mtbot.sixseven.cam`) и никогда с api.telegram.org. Ключ сервера (`mtk_…`) создаётся при
привязке на самом сервере и лежит в `/etc/multitest/agent.conf` (права 600) — вместе с ID сервера и
адресом бота; бот хранит только хеш ключа. Ключ уходит лишь заголовком по https, в `ps` и в выводе
`bash -x` его не видно. В бот отправляются `summary.txt` — данные для поста: адрес **маской**, как на
картинке, железо, ключевые цифры тестов, hostname не отправляется — и PNG страниц альбома. Протокол
целиком — в [docs/telegram-protocol.md](docs/telegram-protocol.md).

Если сервер отвязали в боте, при следующей отправке скрипт сам удалит ключ. Если бот недоступен,
мультитест всё равно доделает сводку и imgdb-ссылку.

**Запуск тестов из Telegram.** После привязки скрипт отдельно спросит, разрешить ли запуск из бота.
Согласие ставит службу `multitest-agent` (systemd): раз в ~25 секунд она спрашивает у бота задание и
запускает **только** тесты Multitest из каталога — выбранные в боте кнопками. В бот идёт прогресс
(«3 из 7, сейчас YABS»), кнопка «Остановить» гасит текущий тест вместе с дочерними процессами, а
сводка из готовых тестов приходит, как после ручного запуска: альбом, пост и редактор.

- Агент ничего не меняет в системе (BBR, IPv6 — только руками), лишь ставит пакеты для тестов, как и
  ручной запуск. Входящих портов не открывает: соединения только исходящие, к API бота.
- Лимиты — на сервере, бот их обойти не может: не чаще раза в 15 минут, до 6 прогонов в сутки, тяжёлых
  (YABS, iPerf3, bench.sh) — до 2. Свои значения — строками `MT_LIM_GAP=…` (секунды), `MT_LIM_DAY=…`,
  `MT_LIM_HEAVY=…` в `/etc/multitest/agent.conf`.
- Ручной мультитест и задание из бота не идут одновременно: второй дождётся первого.
- Тест, зависший дольше трёх своих обычных времён (не больше 30 минут), останавливается сам; весь прогон —
  не дольше часа.
- Выключить: Утилиты → Telegram-бот → «Запуск тестов из Telegram — выключить». Отвязка выключает и службу.
  Журнал: `journalctl -u multitest-agent`.
- Службе нужен скрипт файлом, `/usr/local/bin/multitest`: если multitest запущен через `bash <(curl …)`,
  скрипт сам скачает свежую версию и проверит, что она умеет агента.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MT_TG` | `1` | `0` — не отправлять сводку в Telegram, даже если сервер привязан |
| `MT_IMGDB` | `1` | `0` — не заливать альбом на imgdb (если сервер привязан, сводка уйдёт в бота) |

## Зависимости

Скрипт автоматически установит недостающие пакеты:

- `curl`
- `wget`
- `sysbench`

Поддерживаемые пакетные менеджеры: `apt`, `dnf`, `yum`, `apk`, `pacman`.

## Требования

- Linux (Debian/Ubuntu, CentOS/RHEL, Fedora, Alpine, Arch)
- Права root (для установки пакетов и утилит)
- Bash 4+
